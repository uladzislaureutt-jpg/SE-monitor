# Update81: результаты и границы проверки

## Что изменено

Сборка `2026-09-04.social.81-run44-balanced-integrity-1.0`, основа — update80.
Порог релевантности, источники и временное окно не ослаблялись. Добавлены
связанные признаки общественной проблемы: предмет → конкретный вред/нарушение
→ масштаб, повторяемость либо подтверждение. Само слово «жалоба» не стало
универсальным пропуском.

Восстанавливаются восемь типов сюжетов, выявленных в прогоне №44:

- многолетняя ошибочная маршрутизация грузовиков во двор, несмотря на обращения;
- массовые нарушения приватности и рост жалоб на персональные данные;
- невыплаченный расчёт при увольнении и нарушение трудовых прав;
- чрезмерные смены, о которых работник обратился за защитой;
- остановка пищевого производства вследствие санитарных нарушений;
- системная перегрузка дворов автомобилями;
- повторяющиеся жалобы покупателей на обслуживание;
- ухудшение качества коммунальной воды из-за износа оборудования.

Сохранена защита ранее добавленных обращений граждан, коллективного
потребительского ущерба и сюжетов из прогонов №42–43. Извинение магазина само
по себе не доказывает массовость. Нейтральный график 8–9 часов не становится
нарушением трудовых прав. Зарубежная вакцина не получает безусловный проход
только из-за масштаба вреда: требуется связь с белорусским рынком.

Сужены проходы для розыска пропавших, дорожной профилактики и запуска камер,
юридических справок для бизнеса, сообщений о высоких заработках, экспортного
продвижения, опровержений проблемы, компенсированной транспортной пересадки
и реакции на цену одного частного продавца. Защитные исключения для реальной
общественной проблемы сохранены. Поэтому это не обещание удалить любой
сюжет похожего жанра: маркетинговая публикация с историей обрушения остаётся
пограничной и не исключается ценой отключения этих защит.

## Релевантность: архивный replay

| Набор | Проверено | REJECT → KEEP | KEEP → REJECT | Без изменения |
| --- | ---: | ---: | ---: | ---: |
| Прогон №44 | 573 | 10 | 9 | 554 |
| Прогон №43 после update80 | 81 | 0 | 0 | 81 |

В десяти возвращённых публикациях — восемь самостоятельных проблем:
по санитарному цеху и персональным данным есть по две версии. Это **число
изменившихся решений классификатора**, а не прибавка десяти карточек к отчёту.
Архивные исходные метки — SILVER, а не независимая истина. Причины и URL
каждого решения сохранены в `validation/update81/`.

Все источники этих двух архивов сопоставились с локальной конфигурацией.
Проверка использует сохранённый `semantic_model_text`, который может быть
усечён. Не воспроизводились сетевой сбор, отсечение по времени, отбор цитат,
история ранее опубликованных событий и действие семантической модели.
Нельзя переносить эти числа на весь поток источников или считать их
оценкой precision/recall на новом blind GOLD.

## Целостность событий

Причина части дублей оказалась общей: краткая цитата для отчёта теряла
числовые признаки, а событие общереспубликанского масштаба наследовало город
редакции. Теперь числовые признаки ограниченного начала исходного текста
сохраняются отдельно для узких семейств событий. Сопоставление сохраняет
защиту разных мест, развития события, аналитики и временного расстояния.
Для отключения воды дополнительным якорем служит совпадающий именованный
агрогородок при том же основном населённом пункте и дне публикации.

Воспроизводимая проверка `check_update81_report_identity.py` использует
26 исходных карточек отчёта №44, обогащённых сохранёнными входами; после
объединения трёх пар остаются 23 карточки (DNS, Любань, опрос о ветуслугах). Это отдельная
проверка идентичности, без пересчёта релевантности. Фактические объединения
перечислены в `run44-identity.json`. Их нельзя складывать с таблицей выше
для предсказания конечного размера отчёта.

Исправляется и обрезанный автоматически сформированный заголовок
«Напомним, ранее в министерстве»: восстанавливается полное предложение
из исходного текста. Редакторские заголовки источников не переписываются.

## GOLD и семантический слой

Ручные метки и locked GOLD не изменены; новые тестовые примеры не добавлены
к нему скрыто. На этом этапе не публикуется новая метрика GOLD: в исходном
наборе есть карточки без полного текста, а повторное использование набора
после разработки правил не было бы новым слепым испытанием.

Семантическая модель не устанавливается и не активируется этим пакетом.
Она остаётся дополнительным фильтром поверх regex, а не заменой. Для решения
об активном veto/rescue нужны отдельные пороги и проспективная редакторская
проверка. Самостоятельно менять keep/reject редактора пакет не будет.

## Проверка установки

Все 604 теста прошли. Команды, ограничения и откат — в `INSTALL-UPDATE81.md`. JUnit-результаты
регрессионного набора находятся в `validation/update81/pytest.xml`.
В комплект включены сценарии update77–81 и исправление устаревшей записи
lint-теста. Восстановлен README уже существующего контракта raw_history
из update77; ни данные архивов, ни правила их хранения этим не меняются.

Следующий практический шаг после установки — обычный прогон с сохранением
report/debug. Он проверит полный конвейер на новых публикациях; редакторская
оценка новых пограничных сюжетов остаётся за пользователем.
