# S-monitor update 76: guarded recall по аудиту запуска 39

Build: `2026-09-03.social.76-guarded-recall-report39-1.0`

## Основание

Независимый повторный мониторинг источников запуска 39 показал, что
существенные материалы были успешно обнаружены и загружены, но затем
отклонены фильтром релевантности. Основные причины — слишком буквальная
связка «тема + проблема» и два широких veto: любое упоминание Лукашенко
считалось политическим сюжетом, а любое упоминание РУВД — криминальной
хроникой.

Редакционное решение для update76: восстановить все подтверждённые пропуски
и принятые пограничные классы, не снижая общий порог и не ослабляя
существующие жанровые исключения.

## Архитектура изменения

Добавлен слой `PROTECTED_PUBLIC_ISSUE_PATTERNS`. Это не белый список
заголовков и не набор исключений для конкретных сайтов. Каждый профиль
срабатывает только в первых шести предложениях и требует одновременно:

1. предмет социальной или социально-экономической проблемы;
2. конкретный ущерб, ограничение, неисполнение или ухудшение;
3. масштаб/общественную значимость: группу затронутых людей, повторные
   обращения, длительность, массовую реакцию либо иной маркер публичной
   подотчётности.

Глобальный `minimum_score`, словари общих негативных слов, географический
фильтр, списки источников, лимиты кандидатов и все обычные veto сохранены.

### Адресат обращения не равен теме публикации

Имя Лукашенко больше не блокирует материал, если в ограниченном лиде есть
одновременно обращение к власти, обычная категория мониторинга и конкретная
нерешённая проблема. Политические выступления, выборы, санкции и иные
политические сюжеты по-прежнему исключаются.

### Канал защиты прав не равен криминальной хронике

Упоминание РУВД не блокирует массовое неисполнение оплаченных заказов, если
есть товар/услуга, доказанное неполучение и отдельный маркер масштаба
(например, десятки/сотни пострадавших или группа жалоб). Единичное
мошенничество или частный спор исключаются как прежде.

## Восстановленные классы

- длительные проблемы с питьевой водой и коммунальной инфраструктурой;
- протечки после ремонта и вынужденное переселение при капремонте;
- коллективные требования светофора/безопасного перехода;
- системные барьеры при трудоустройстве;
- несоответствие обещанной образовательной услуги и плохие учебники;
- ухудшение условий массовой услуги связи;
- потеря доступа к банковской услуге у опекунов и уязвимых групп;
- массовое неисполнение оплаченных заказов, включая «Кухни Черри»;
- общественная реакция на обязательный скрининг и досмотры школьников;
- перенос/демонтаж мемориала вопреки мнению жителей;
- свидетельства пенсионеров о доходе ниже фактических расходов;
- пробелы в компенсации общежития молодым специалистам;
- ненадлежащие условия студенческих общежитий с общественным резонансом;
- медленное устранение коллективной проблемы контейнерных площадок;
- продолжение резонансного сюжета о школьных правилах внешнего вида.

Дополнительно нейтральный агрегат дефицита регионального бюджета теперь не
ошибочно трактуется как потребительский дефицит без установленного
последствия для жителей.

## Точность и тесты

Добавлен файл `tests/test_update76_guarded_recall_report39.py`:

- 19 положительных регрессий по подтверждённым пропускам и принятым
  пограничным сюжетам;
- 15 отрицательных регрессий по известному шуму;
- отдельные контрастные тесты «политическое выступление / обращение о
  нерешённой проблеме» и «единичный спор / массовое неисполнение заказов».

Полный результат: `550 passed`.

## Совместимость с update75

Сохранены без изменения workflow и условия архивирования плановых прогонов.
В пакет добавлен отсутствовавший в исходном ZIP файл
`data/ml/raw_history/README.md`, который уже требовался тестом update75.
Также синхронизирован lint-baseline с ранее внесённым в update75 сужением
белорусского шаблона условий труда. State, discovery cache и архивы прогонов
не входят в пакет и не заменяются.

## Установка

Пакет предназначен для установки поверх `SE-monitor-main (7).zip`.
Скопируйте содержимое каталога пакета в корень репозитория с заменой
одноимённых файлов, сверьте `MANIFEST.sha256`, затем выполните:

```bash
python -m pytest -q
```

Для первой производственной проверки рекомендуется dry-run. Для отката
верните одним commit пути из `MANIFEST.json`; `data/state.json`,
`data/discovery_cache.json` и `data/ml/raw_history/articles|rejected`
откатывать не нужно.
