# Semantic dual-head experiment

Этот каталог фиксирует следующий экспериментальный контур после blind-eval
1.0. Он **не подключён к рабочему мониторингу** и не меняет regex-решения.

## Почему нужны два маршрута

Первый blind GOLD показал, что единый классификатор смешивает две разные
редакторские задачи. Для `regex KEEP` нужно распознавать отсутствие проблемы,
сервисные объяснения, уже устранённые случаи и единичные происшествия. Для
`regex REJECT` нужно распознавать обращения, коллективный ущерб, дефицит услуг
и массовый потребительский интерес. Цена ошибки у маршрутов также различна.

- `veto`: вход — только regex-`KEEP`; положительная метка действия означает
  редакторский `REJECT`.
- `rescue`: вход — только regex-`REJECT`; положительная метка действия означает
  редакторский `KEEP`.
- `BORDERLINE` нельзя автоматически преобразовывать в бинарную метку; сначала
  требуется отдельная адъюдикация.

## Порядок работы

1. Накопить `data/ml/raw_history/semantic_inputs/` после update77.
2. Сформировать независимую ручную выборку с event-safe дедупликацией.
3. Разметить её без показа ожидаемого ответа модели.
4. Разделить события на development/calibration/test до обучения.
5. Обучать и калибровать `veto` и `rescue` отдельно. Базовый кандидат для
   следующего эксперимента — `intfloat/multilingual-e5-small`, поскольку он был
   лучшим из проверенных, но его веса и пороги нельзя переносить из blind-eval
   1.0.
6. Прогнать не менее 7–14 реальных запусков в shadow-режиме.
7. Только после нового проспективного blind GOLD рассматривать влияние на
   отчёт. `rescue` требует более строгого порога, чем `veto`.

Текущий GOLD от 2026-09-03 после просмотра результатов становится
диагностическим benchmark и development-материалом. Повторно выдавать его за
независимый blind test нельзя.
