# S-monitor — эксперимент SetFit с более крупным энкодером 2.0

Это отдельный ручной эксперимент. Он не подключён к `social_monitor.py`, не
имеет расписания и не читает/не изменяет рабочие `state.json`,
`discovery_cache.json`, секреты, email или отчёты мониторинга.

## Что проверяется

- модель `intfloat/multilingual-e5-small` с файлом весов около 471 МБ;
- та же event-safe выборка и те же параметры допуска, что в компактном пилоте;
- изменение качества относительно компактного SetFit и TF-IDF baseline;
- техническая устойчивость ручного CPU-запуска в GitHub Actions.

Модель выбрана как умеренное увеличение: 12 слоёв, 384-мерные представления,
94 языка и контекст до 512 позиций. В репозиторий веса не добавляются.

## Ограничение оценки

GOLD из пилота 1.0 уже был раскрыт при выборе следующего эксперимента. Поэтому
он теперь называется `legacy_benchmark` и используется только для сравнения.
Даже хорошие метрики не дают разрешения на теневой или рабочий запуск.
Окончательный допуск требует нового, не использованного ранее GOLD-набора из
последующих плановых мониторингов.

## Результат workflow

Artifact `s-monitor-setfit-large-experiment-results` содержит только небольшие
CSV/JSON/TXT-диагностики. Файл весов около 471 МБ остаётся на временном runner и
не загружается в artifact. Итоговое решение этого этапа всегда
`AWAIT_NEW_BLIND_GOLD`.

## Неизменяемые компоненты

- `social_monitor.py`, `main.py`, `config/`;
- рабочий workflow и расписание;
- `data/state.json`, `data/discovery_cache.json`;
- источники, фильтры, дедупликация и доставка;
- GitHub secrets.

## Откат

Удалить `.github/workflows/social-setfit-large-experiment.yml`,
`ml/setfit_large_experiment/` и `control_reference/`. Рабочий мониторинг от них
не зависит. `data/ml/event_safe_v1/` можно оставить: это тот же набор пилота 1.0.
