# Update81 — установка и проверка

Пакет для установленного update80. Это обновление фильтров и целостности
результатов, не включение семантической модели в боевой режим.

## Установка

1. Сохраните текущую версию репозитория отдельным коммитом или резервной копией.
2. Распакуйте архив в отдельную папку. Скопируйте **его содержимое в корень
   репозитория**, сохраняя вложенные каталоги `tests/`, `scripts/`, `data/`
   и `validation/`. Подтвердите замену одноимённых файлов. Не складывайте
   файлы из вложенных каталогов непосредственно в корень.
3. Проверьте, что изменились только файлы из `SHA256SUMS-update81.txt`.
   Если `social_monitor.py` уже изменён после update80 вручную, сначала
   согласуйте diff: этот пакет содержит целиком новый файл, а не автослияние.
4. Из корня выполните:

```bash
python -m pip install -r requirements.txt pytest
python -m pytest -q
python -c "import social_monitor as m; print(m.MONITOR_BUILD)"
```

Ожидаемая сборка: `2026-09-04.social.81-run44-balanced-integrity-1.0`.
Дата — привязка к анализируемому прогону, не время установки.

`config/settings.yaml`, список источников, workflow, секреты, состояния
предыдущих прогонов, GOLD и веса моделей пакет **не заменяет**. Вызовов
Hugging Face и новых runtime-зависимостей в нём нет.

## После установки

Выполните один обычный запуск и сохраните report и debug. Проверьте сборку,
ошибки извлечения, новые KEEP/REJECT и итоговую дедупликацию. Архивный replay
не гарантирует тот же размер отчёта: сбор, время публикаций и доступность
текстов при следующем запуске будут другими.

Не включайте semantic veto/rescue в активный режим по результатам этого
пакета. Целевая архитектура прежняя: regex-база → дополнительный семантический
слой; до отдельной проверки его решения не меняют отчёт. Для выпуска
второго слоя нужна новая проспективная редакторская оценка, независимая от
случаев, на которых дорабатывались правила.

## Воспроизводимость

```bash
python scripts/replay_update81.py --input /path/to/semantic_training_signals.csv --output /path/to/replay.json
```

С `--baseline /path/to/update80/social_monitor.py` обе версии проверяются
на одном входе. Скрипт ничего не скачивает и не меняет состояние мониторинга.
Отчёт содержит решения по всем строкам, причины, хеши и несовпавшие источники.
Используются архивные нормализованные тексты, иногда усечённые; это проверка
релевантности, **не replay всего production-конвейера**.

При откате восстановите изменённые файлы из своей резервной копии/коммита.
Не откатывайте и не удаляйте накопленные архивы и ручную разметку.
